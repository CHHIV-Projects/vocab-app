## Persistence architecture

The additive migration creates:

```text
schema_migrations
lexical_entries
lexical_entry_versions
lexical_flags
```

`lexical_entries` provides one normalized logical word and an `active_version_id`. `lexical_entry_versions` stores immutable accepted candidate and exact evidence JSONB snapshots, evidence hash, resource/model/prompt/policy/schema/packer/validator/inference identities, candidate identity, origin, and version number. `lexical_flags` uses unique candidate identity for single-user idempotency.

Existing `vocabulary` remains the lightweight practice projection. Save updates the first displayed core definition/POS projection while preserving the existing vocabulary row and count; a new word creates one practice row. Previous rich accepted versions remain retained.

The migration runner uses ordered SQL, `schema_migrations`, and `pg_advisory_xact_lock`. The live existing database was migrated without destroying its volume or rows.

## M004.4 integration

Validated candidates retain `evidence_snapshot` containing the normalized M004.4 synthesis projection. Retry verifies the stored snapshot hash and calls synthesis with that snapshot directly; it does not call current lexical lookup. Refresh separately compares current exact-word projected evidence against the saved hash and synthesizes only after an explicit action.

The current workflow searches exact words through the M004.4 provider/cache path and loads an active accepted version without invoking GPT when one exists. Refresh hash comparison uses the full projected evidence hash, including WordNet evidence.

## Synonyms

Deterministic Wiktionary synonym enrichment maps:

```text
source sense relation
    -> canonical source sense ID
    -> final learner group
    -> synonym term + all supporting relation evidence IDs
```

The normal enrichment path keeps at most five case-folded unique terms per learner meaning while retaining provenance internally. WordNet remains separate supplemental evidence and is not asserted equivalent to Wiktionary senses. Unsupported terms cannot be introduced by this deterministic mapping.

## Etymology

Etymology is a separate bounded enrichment call. It consumes only canonical etymology text/templates and requires a nonempty summary plus valid canonical etymology evidence IDs. If no source etymology exists, no call is made. The enriched candidate retains the summary and evidence references. Uncertainty is delegated to the model under an explicit source-only prompt and remains subject to structural evidence validation.

### Meander Save incident

The Product Owner's first Save attempt reported:

```text
Lexical workflow failed: 0
```

Read-only database inspection showed the Save transaction left no partial state:

- no `meander` vocabulary row;
- no `lexical_entries` row;
- no `lexical_entry_versions` row;
- no `lexical_flags` row;
- legacy totals remained two vocabulary rows with total practice count two.

The root cause was `KeyError(0)` in `PostgresPersistence.save_accepted_version()`. The live psycopg connection uses `dict_row`, but Save indexed `fetchone()` results with `[0]` for returned IDs and the version aggregate. The controller therefore surfaced a persistence exception through the overly broad old `Lexical workflow failed` boundary.

The correction adds one row-shape helper supporting both dictionary and tuple rows, aliases the aggregate as `next_version`, and uses named keys for returned IDs. Save errors now render as `Save failed. The entry was not saved.` while retaining the candidate; Retry, Refresh, and Flag have separate action error messages.

The isolated PostgreSQL Save/version/Flag suite passed after this correction. No real Product Owner Save was retried. The live Meander database state remains empty for accepted lexical data.

### Product Owner lexical mount incident

The first Product Owner browser search exposed:

```text
Lexical workflow failed:
[Errno 13] Permission denied: '/lexical-data/active'
```

Root cause was a host/container identity mismatch, not an incorrect Compose mount. The actual app process is `uid=10001(vocab) gid=10001(vocab)`, while the host lexical tree is owned by `1000:1000` with owner-only modes:

```text
/home/chuck/.local                 700
/home/chuck/.local/share           700
/home/chuck/.local/share/vocab-lexical 700
active                              600
```

The actual mount remains:

```text
/home/chuck/.local/share/vocab-lexical:/lexical-data:ro
```

The minimum correction was a per-UID POSIX ACL for `10001`, granting only:

- traverse (`x`) on `/home/chuck`, `.local`, and `share`;
- traverse/read (`rx`) on the lexical root and `versions` directories;
- read (`r`) on `active`;
- traverse/read on the active version directory;
- read (`r`) on `lexical.sqlite`.

Owner modes, ownership, dataset content, hashes, and the Docker `:ro` mount were preserved. No `chmod 777`, recursive ownership change, dataset rebuild, or SQLite mutation was performed.

The read-only mount then exposed a second runtime detail: default SQLite opening attempted sidecar lock/journal access and failed with `unable to open database file`. The lexical engine now opens the immutable versioned SQLite artifact using `file:<path>?immutable=1`, which is appropriate for the checksummed immutable lexical projection and performs no writes.

Post-fix in-container verification as uid `10001` succeeded:

```text

resolved = /lexical-data/versions/wiktionary-20260901/lexical.sqlite
archipelago = 2 entries, 6 senses, 0 WordNet synsets
```

WordNet was absent from the slim application image during this direct probe; the optional supplemental lookup now degrades to an empty WordNet collection rather than blocking Wiktionary lexical lookup. The app and PostgreSQL remained healthy. ### Product Owner runtime-path incident

After Incident 1, the Product Owner reported a second browser failure after approximately 6-10 seconds:

```text
Lexical workflow failed:
[Errno 13] Permission denied: '/home/chuck'
```

The exact controlled traceback reproduced the operation as `pathlib.Path.mkdir(parents=True, exist_ok=True)` while `SynthesisRuntime` attempted to create its default `synthesis-cache` path under `/home/chuck/.local/share/vocab-app/runtime`. `/home/chuck` does not exist as a writable container path for uid `10001`; this was accidental host-path leakage from the old `SynthesisRuntime` default, not a lexical mount or WordNet failure.

The correction was:

```text
host:      /home/chuck/.local/share/vocab-app/runtime
container: /vocab-runtime:rw
VOCAB_RUNTIME_ROOT=/vocab-runtime
```

The lexical evidence mount remains read-only. No host home directory was mounted broadly, and no root execution or broad permission change was used.

The final WordNet configuration is:
