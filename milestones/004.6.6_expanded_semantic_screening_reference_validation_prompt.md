# 1. Objective

M004.6.6 follows the completed M004.6.5 high-recall semantic pair screening experiment.

M004.6.5 established a promising but still under-validated screening architecture:

canonical source senses
    ->
deterministic POS/material partitioning
    ->
definition-focused semantic embedding
    ->
high-recall candidate-pair screening
    ->
Qwen3:8b single-pair bounded semantic judgment
    ->
conservative code-owned complete-link clustering
    ->
learner-meaning containers

The M004.6.5 benchmark used:

- embedding model: `nomic-embed-text:latest`;
- embedding dimension: 768;
- representation: `definition-focused-v1`;
- similarity: cosine;
- provisional best threshold: 0.90.

On the adjudicated M004.6.4 reference, threshold 0.90:

- retained 100% of the four resolved merge-reference pairs;
- removed 86.5% of resolved keep-separate pairs;
- reduced projected comparisons for representative large partitions by approximately 81.5–97.6%.

However, the positive reference contained only four resolved merge examples.

M004.6.5 therefore closed with:

> screening promising, but reference too small for production architecture authorization.

The objective of M004.6.6 is:

> Expand the Product Owner / Architect semantic reference across a broader and more difficult lexical sample, then determine whether the existing M004.6.5 screening architecture continues to preserve legitimate learner-meaning merge candidates while eliminating enough unnecessary pair comparisons to justify future production architecture planning.

This is fundamentally a GENERALIZATION VALIDATION milestone.

The preferred outcome is not to invent a better method.

The preferred outcome is to determine whether the simplest method we already have is trustworthy enough.

# 11. Pair Selection

Do NOT use only random within-partition pairs.

The reference must intentionally cover the decision boundary.

For each selected word/POS partition, construct a manageable candidate set including:

- broader/narrower pairs;

- specialized/general pairs;
- related-but-distinct pairs;
- clearly distinct controls.

Embedding similarity may be used to SURFACE pairs for human adjudication.

It must NOT determine their reference label.

# 14. Learner Consolidation Policy

Use the accepted M004.6.4 policy.

MERGE only when senses express substantially the same learner-facing concept and differ primarily by:

- wording;
- near-paraphrase;
- duplicate dictionary phrasing;
- minor contextual application;
- ordinary example/context variation.

KEEP SEPARATE when:

- the learner needs a meaningfully different use;
- one is a significant specialization;
- grammatical behavior materially changes the use;
- technical/domain distinction deserves independent learner treatment;
- combining them would create an overbroad definition;
- material-label boundaries require separation.

UNCERTAIN / REVIEW when:

- reasonable learner-facing designs could defensibly merge or separate;
- product policy remains ambiguous;
- source evidence is insufficient.

Prefer false split over destructive false merge.
