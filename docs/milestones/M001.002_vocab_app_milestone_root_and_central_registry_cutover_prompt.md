# M001.002 — Vocab App Milestone-Root and Central-Registry Cutover

## 1. Objective

Complete the Vocab App onboarding cutover from the temporary repository-root `milestones/` layout to the accepted Repo Control structure under `docs/`, while preserving historical evidence and keeping the active lifecycle recoverable throughout the transition.

This milestone must:

- establish `docs/milestones/` as the canonical Repo Control-managed milestone root;
- relocate legacy pre-Repo-Control milestone evidence to `docs/history/milestones/` without letting it pollute active milestone discovery;
- relocate the closed M001.000 and M001.001 lifecycle artifacts to `docs/milestones/`;
- transition the active M001.002 prompt/workflow safely to `docs/milestones/`;
- update the central Repo Control II repository registry to the canonical Vocab mappings through a Product Owner-controlled cutover step;
- verify browser, Architect MCP, and Coder CLI all resolve the same Vocab repository and canonical governing paths after cutover;
- leave the old root `milestones/` retired and non-authoritative.

This milestone is onboarding/infrastructure only. It does not authorize Vocab application feature work.

`milestones/M001.002_vocab_app_milestone_root_and_central_registry_cutover_prompt.md`

### Phase A — Coder prepares new-root state while old root remains authoritative

The Coder may copy/move closed and historical artifacts as specified below, and must create synchronized copies of the active M001.002 prompt/workflow under `docs/milestones/`.

The Coder must not remove the old-root active M001.002 prompt/workflow during Phase A.

After successful reselection, the Coder resumes validation under the new root and retires the old-root duplicates.

At no point should the Coder attempt to modify Repo Control II's central registry.
