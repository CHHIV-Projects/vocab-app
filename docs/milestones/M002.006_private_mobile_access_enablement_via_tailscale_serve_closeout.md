## 4. Architecture / Integration Notes

The application has two explicit host bindings for its existing container port: LAN traffic enters through `192.168.1.173:8501`, while Tailscale Serve connects through `127.0.0.1:8501`. Serve proxies to the loopback binding and remains governed by tailnet access controls. Funnel, public reverse proxies, router port forwarding, ACL redesign, and exit-node configuration are outside this milestone and were not enabled.

Tailscale Serve required HTTPS/Serve enablement by the Product Owner through the Tailscale administrative boundary. The Product Owner confirmed that action; no consent URL or token was recorded. The configured command uses `tailscale serve --bg 8501`. The installed CLI's background mode stores the configuration in the Tailscale daemon for persistence across daemon restarts; a daemon restart or host reboot was not performed to test recovery.

The app-only deployment used the existing runtime environment and replaced only `vocab-app`.
