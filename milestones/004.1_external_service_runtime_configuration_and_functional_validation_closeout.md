## 9. Translator validation

The original live container check returned:

`GoogleTranslator('hello' -> Spanish) = Hola`

The exact reverse-language diagnosis returned:

- `GoogleTranslator(source='auto', target='en').translate('caliente')` -> unchanged `caliente`;
- `GoogleTranslator(source='es', target='en').translate('caliente')` -> `TranslationNotFound`;
- `GoogleTranslator(source='es', target='en').translate('hola')` -> `TranslationNotFound`;
- `GoogleTranslator(source='fr', target='en').translate('bonjour')` -> `TranslationNotFound`;
- `GoogleTranslator(source='de', target='en').translate('hallo')` -> `TranslationNotFound`.

The bounded correction added explicit `Translate from` and `Translate to` controls and rejects unchanged source text rather than presenting it as successful output. The LAN UI confirmed `Spanish` -> `English` for `caliente` now surfaces the provider error:

`Error: caliente --> No translation was found using the current translator? Try another translator?`

This is a provider failure, not silent application success. `hello` -> Spanish had previously rendered `Spanish: Hola`, but the required current two-direction PASS evidence is incomplete because reverse-language translation is unavailable.
