# B. Standard App-Only Deployment Procedure

Define and, where useful, implement a minimal operator-safe procedure for deploying an already accepted Git revision to the normal LAN application service.

The canonical sequence should include:

1. verify exact repository, branch, HEAD, and clean worktree;
2. verify runtime env file exists and required variable names are present without echoing values;
3. inspect current Compose status;
4. rebuild/recreate ONLY the `vocab-app` service using the runtime env file;
5. do not rebuild, recreate, remove, or reset `vocab-db`;
6. wait for the application health check to reach healthy state;
7. verify the LAN health endpoint at port 8501;
8. verify source parity between accepted checkout and running container;
9. perform a minimal browser smoke check at the canonical LAN endpoint;
10. report exact deployment identity/results.

Expected deployment shape:

```bash
docker compose --env-file /home/chuck/.config/vocab-app/runtime.env \
  up -d --build --no-deps vocab-app
```

Do not blindly encode this example if inspection shows the current source requires a safer equivalent. Current Compose/source is authoritative.

# C. Deployment Verification / Source Parity

A healthy container is not sufficient evidence that it runs the accepted source.

Create a durable source-parity verification procedure.

At minimum compare SHA-256 hashes between the host checkout and running app container for:

- `app.py`;
- `vocab_workflow.py`;
- `vocab_lexical_engine.py`.

If other files materially determine the deployed application identity (for example `requirements.txt`, Dockerfile, or another runtime module), evaluate whether they should also be included.

Requirements:

- parity output must not disclose secrets;
- mismatch must be treated as failure, not informational;
- health + parity together establish deployed-source acceptance;
- do not claim that Git HEAD alone proves container source identity.

Prefer a small deterministic operator command/script only if it meaningfully reduces mistakes. Avoid building a deployment framework.
