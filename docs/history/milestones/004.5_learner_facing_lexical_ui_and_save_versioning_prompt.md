Previous accepted versions must remain internally retained.

11. RETRY
======================================================================

Retry means:

    same exact evidence
    same evidence_set_hash
    new explicit GPT synthesis attempt

Retry is appropriate when the valid result is factually supported but the
presentation/organization is unsatisfactory.

Rules:

- Retry is an explicit user action.
- No hidden/automatic retry.
- Retry bypasses the ordinary validated search cache.
- Retry uses the same exact evidence state.
- Retry must use a new controlled/recorded inference attempt identity/seed
  if the provider supports it.
- Retry creates an unsaved candidate.
- It must NOT replace the active saved version.
- User may Save the candidate, Retry again, Flag it, or search elsewhere.

For a saved word, Retry must use the saved version's evidence state,
not silently use newer canonical evidence.

If the implementation cannot reliably reconstruct/retrieve that exact evidence,
STOP and escalate rather than approximating it.

======================================================================
12. REFRESH
======================================================================

Refresh means:

    new canonical evidence
    -> new synthesis candidate

Refresh is available only when:

    current canonical evidence_set_hash
        !=
    active saved version evidence_set_hash

A newer globally active lexical dataset by itself is not enough.

If the queried word's evidence did not materially change:

    Refresh is unavailable/disabled.

When Refresh is available:

- active saved version remains unchanged;
- current canonical evidence is synthesized into a candidate;
- the candidate must validate normally;
- the candidate does not become accepted until Save;
- Save creates a new accepted version;
- prior accepted version remains retained.

No silent auto-refresh.
