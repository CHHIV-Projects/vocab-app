## 5. Partition Domain

`ConsolidationPartition` preserves:

- normalized lemma;
- POS;
- exact material-label signature;
- existing evidence identity;
- stable source-sense member order;
- deterministic partition identity.

Members are ordered by `(source_order, sense_id)`. Partition identity is a canonical hash of the partition contract, lemma, POS, material signature, evidence identity, and ordered source-sense IDs.

## 6. Alias Contract

Aliases are generated solely from stable member order:

```text
S001 -> first source sense
S002 -> second source sense
...
```

The domain exposes both forward and reverse mappings. No model-generated alias is accepted.

## 7. Pair Enumeration

For `N` members, expected pairs are `N * (N - 1) / 2`.

Pairs are unordered, self-pair-free, partition-local, deterministically ordered, and contain lexically ordered source IDs. The logical pair ID is a canonical hash of:

- structural logical-pair schema version `sense-pair-v1`;
- partition ID;
- ordered source-sense IDs.

Reversing A/B input produces the same pair ID.

## 8. Pair-Judgment Identity

Pair judgment identity is separate from structural pair identity:

```text
hash(
  logical_pair_id,
  evidence_identity,
  partition_identity,
  pair_judgment_contract_version,
  semantic_model_identity,
  semantic_options_identity
)
```

Evidence identity, partition identity, contract version, model digest, and semantic options therefore invalidate cached semantic output when changed. Runtime-only metadata is excluded.

The identity hierarchy is:

```text
partition identity
    ->
logical pair identity
    ->
pair-judgment input identity
    ->
validated pair-judgment result identity
    ->
topology identity
    ->
container membership identities
```

The validated result identity is a canonical hash of the pair-judgment identity, validated decision, and validated reason. It exists only for `succeeded_validated` judgments.

## 9. Semantic Contract

Contract identity: `pair-judgment-v1-exhaustive-qwen`.

Decision enum:

```text
merge | keep_separate | uncertain
```

Reason enum:

```text
paraphrase_or_duplicate
contextual_variant
specialized_subsense
broader_or_narrower
related_but_distinct
materially_different
insufficient_evidence
```

The established incompatible combinations are rejected. `uncertain` is valid completed judgment evidence but is a blocked topology edge.

## 10. Coverage Invariant

Topology finalization requires:

- exact expected versus actual logical pair coverage;
- every expected pair appearing exactly once;
- no foreign pair;
- no missing pair;
- compatible partition, evidence, contract, model, and options identities;
- every pair in `succeeded_validated` state.

Any retryable, terminal, missing, duplicate, foreign, or incompatible pair blocks normal finalization. Diagnostics identify the specific failure categories and IDs.

## 11. Complete-Link Algorithm

The engine starts with singleton containers in stable source-sense order. It scans container pairs deterministically and merges only when every cross-container pair has a validated `merge` judgment. After each merge, scanning restarts. It stops when no legal merge remains.

`keep_separate` and `uncertain` both block a merge. Naive union-find is not used.

The non-transitive fixture:

```text
A-B = merge
B-C = merge
A-C = keep_separate
```

does not produce one three-member container. The deterministic result is `A,B` together and `C` separate.

## 12. One-Sense Fast Path

A one-member partition enumerates zero pairs and requires zero judgments. It still passes through the same partition, container, and topology identity domain and returns one stable container containing the original source-sense ID.

## 13. Container and Topology Identity

Container identity hashes:

- partition identity;
- sorted member source-sense IDs;
- `learner-containers-v1`.

It is independent of learner wording.

Topology identity hashes:

- partition identity;
- the canonically ordered complete set of validated pair-judgment result identities;
- `complete-link-v1`;
- `learner-containers-v1`.

Learner wording and Core/Additional ranking are intentionally absent.
