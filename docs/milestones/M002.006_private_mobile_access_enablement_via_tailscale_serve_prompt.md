# M002.006 — Private Mobile Access Enablement via Tailscale Serve

**Project:** Vocab App  
**Repository:** `/home/chuck/projects/vocab-app`  
**Branch:** `main`  
**Milestone type:** Private remote-access enablement + deployment hardening  
**Primary objective:** Add a private, stable HTTPS access path for Vocab App through Tailscale Serve so the same mobile URL works on home Wi-Fi and external networks, while preserving the existing LAN endpoint, production database, lexical data, and non-public security posture.

## Product / Access Decision

The Vocab App remains a private application.

Accepted existing LAN endpoint:

```text
http://192.168.1.173:8501/
```

M002.006 adds a second access path:

```text
iPhone / tailnet device
    ↓
Tailscale private encrypted network
    ↓
https://henderson-server1.<tailnet>.ts.net/
    ↓
Tailscale Serve
    ↓
http://127.0.0.1:8501
    ↓
Vocab App container
```

The exact `.ts.net` hostname must be discovered from the live Tailscale configuration and recorded; do not invent it.

This milestone authorizes **Tailscale Serve only**, not Tailscale Funnel. The service must remain unavailable to arbitrary public-Internet clients.

The existing LAN endpoint must continue to work after this change.

# A. Add Loopback Access Without Removing LAN Access

Modify the repository-controlled Compose application port publishing so the Vocab app is reachable through BOTH:

```text
192.168.1.173:8501
127.0.0.1:8501
```

Both must map to the existing application container port 8501.

Use the smallest safe Compose change. Explicit host-IP bindings are required; do not replace them with an all-interface bind such as `0.0.0.0:8501`.

Expected conceptual result:

```yaml
ports:
  - host_ip: 192.168.1.173
    target: 8501
    published: "8501"
  - host_ip: 127.0.0.1
    target: 8501
    published: "8501"
```

Short-form equivalents are acceptable if consistent with current project style.

Acceptance:

- `docker compose ... config` resolves cleanly;
- no unintended `0.0.0.0` or public bind appears;
- existing LAN endpoint remains available;
- new loopback endpoint becomes available;
- database topology is unchanged.

If the local Docker/Compose runtime cannot safely publish the same host port on these two explicit host IPs, STOP and raise a bounded Repo Control question rather than broadening the bind.

After loopback health passes, inspect current Serve status again.

If Serve remains unconfigured, configure the Vocab service using the current locally installed Tailscale CLI syntax.

Expected current form:

```bash

```

This is intended to create an HTTPS tailnet-only reverse proxy to:

```text
http://127.0.0.1:8501
```

Requirements:

- use **Serve**, never Funnel;
- use background/persistent Serve mode;
- do not create router port forwarding;
- do not expose port 8501 directly on a public interface;
- do not enable a public reverse proxy;
- do not alter unrelated Tailscale services or ACLs;
- do not select/configure an exit node;
- do not alter the iPhone's general Internet routing.

After configuration:

```bash

```

must show an HTTPS `.ts.net` URL and a proxy target of `http://127.0.0.1:8501`.
