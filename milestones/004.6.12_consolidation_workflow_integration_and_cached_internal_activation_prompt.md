# 1. Objective

M004.6.9 established deterministic pairwise consolidation semantics.

M004.6.10 established durable PostgreSQL consolidation state.

M004.6.11 established the real bounded `qwen3:8b` pair provider plus resumable partition-level orchestration.

M004.6.12 must integrate those pieces into a coherent **word-level internal consolidation workflow**.

The target flow is now:

canonical lexical lookup
    ->
project accepted synthesis/consolidation evidence
    ->
deterministic POS/material partitions
    ->
for each partition:
        reuse completed compatible topology if present
        OR
        create/resume durable consolidation work
    ->
collect validated learner containers across all partitions
    ->
return one deterministic word-level consolidation result

The key requirement is that repeated processing of unchanged evidence must reuse durable semantic work rather than call Qwen again.

This milestone is about **internal workflow activation and cache/reuse behavior**.

It is NOT yet the milestone that generates final learner wording or changes what the user sees in Streamlit.

# 2. Central Question

M004.6.12 must answer:

> Given a normal canonical lexical lookup for a word, can the application deterministically construct all consolidation partitions, create/resume/reuse their durable jobs, obtain complete validated container topology where available, and return one coherent word-level consolidation result without recomputing completed semantic work?

If yes, the consolidation engine is ready to become the semantic foundation for learner wording and ranking in M004.6.13.

# 13. Partition-Level Cache Reuse

For each deterministic partition:

1. construct the same consolidation identity required by M004.6.10/M004.6.11;
2. create/get the compatible durable job;
3. if `topology_validated`, load persisted containers;
4. make ZERO Qwen calls for that partition;
5. include the reused topology in the word-level result.

This is a central acceptance condition.

# 14. Resume Behavior

If a compatible job exists but is incomplete:

- reuse all `succeeded_validated` pair rows;
- resume only valid resumable work;
- do not recompute successful pairs;
- preserve terminal failures;
- finalize only after exact compatible coverage exists.

The word-level workflow must not delete and recreate a partially completed compatible job merely because a new search occurs.

# 15. Evidence Change / Cache Invalidation

If the canonical evidence identity changes:

- the old completed job must not be treated as compatible current work;
- a new consolidation identity must result naturally through the existing identity functions;
- old persisted work remains historical/durable;
- no destructive overwrite occurs.

Do NOT implement manual cache invalidation rules if the accepted evidence/identity chain already provides this behavior.

Test this deterministically.

# 19. Bounded Invocation

M004.6.12 must preserve a caller-controlled work bound.

At the word level support something equivalent to:

- `max_total_pairs`;
- or another clear explicit bounded-work parameter.

The word-level service should distribute this budget deterministically across partitions.

Example:

max_total_pairs = 3

Partition A needs 2 pairs.
Partition B needs 4 pairs.

The invocation may process A's 2 and one pair from B, then return incomplete.

Do not silently exceed the caller's pair-call/work budget.

Already completed/reused pairs do not consume live provider-call budget.

# 21. Word-Level Completion Rule

The word is consolidation-complete only when EVERY deterministic partition has a validated topology.

If:

- any partition is incomplete -> word result is incomplete;
- any partition has terminal failure -> word result is blocked;
- every partition is topology validated -> word result is complete.

Do not treat partial partition success as a complete word result.

# 22. Terminal Failure Behavior

If one partition is terminally blocked:

- preserve completed topologies for other partitions;
- return them as durable internal evidence if useful;
- mark the overall word consolidation as blocked/incomplete;
- do NOT publish a final complete word topology;
- do NOT fabricate fallback grouping.

No GPT fallback.

No "each sense separately" silent fallback unless explicitly authorized in a future milestone.
