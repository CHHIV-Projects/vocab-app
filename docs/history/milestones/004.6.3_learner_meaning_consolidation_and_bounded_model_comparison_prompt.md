# 1. Objective

M004.6.3 follows M004.6.2, which established:

- a repeatable Tier 1 benchmark framework;
- 720/720 structurally valid core-selection calls across both installed models and both contracts;
- materially lower bounded-task latency from `qwen3:8b`;
- no current structural reason to replace Ollama;
- fixed-key ranking is structurally safer by construction;
- semantic model/contract superiority is not yet established;
- the reconstructed M004.6.2 fixtures exposed an important limitation: taking a bounded set of raw Wiktionary glosses does not reliably produce representative learner meanings.

The next problem is therefore upstream of final core ranking.

The objective of M004.6.3 is:

> Determine whether fine-grained lexical senses can be reliably consolidated into higher-level learner-meaning containers using deterministic code ownership plus bounded AI semantic judgments, and then determine whether those containers provide a trustworthy basis for learner-relevance ranking.

The intended conceptual pipeline is:

raw canonical lexical senses
    ->
deterministic normalization and partitioning
    ->
bounded semantic-equivalence judgments
    ->
code-owned learner-meaning containers
    ->
bounded learner-relevance scoring
    ->
code-owned Core Meanings + Additional Meanings

This milestone should answer:

1. Can we construct learner-meaning containers without allowing the model to own IDs or topology?
2. Can closely overlapping source senses be consolidated without collapsing genuinely distinct meanings?
3. Does `qwen3:8b` perform bounded semantic-equivalence judgments credibly compared with `gpt-oss:20b`?
4. Does a container-based candidate set improve the quality of core-selection inputs compared with the crude raw-gloss fixtures from M004.6.2?
5. Can deterministic code preserve every source sense and its provenance while AI supplies only semantic judgments?
6. Is pairwise/small-batch equivalence practical on difficult words without embeddings?
7. Is the evidence sufficient to proceed to an embedding-screening experiment in M004.6.4?

This milestone is NOT:

- a production grouping rewrite;
- a production core-selection change;
- an embedding implementation;
- a full lexical benchmark;
- a runtime bake-off;
- a new-model benchmark;
- a fine-tuning milestone;
- a generalized autonomous-agent architecture.

# 6. Architectural Principle

This milestone must preserve the following authority boundary:

> AI decides bounded semantic relationships. Code owns source identity, candidate identity, topology construction, complete coverage, ordering, validation, and acceptance.

The model must NOT be asked to:

- invent learner-meaning group IDs;
- return arbitrary group structures;
- silently drop source senses;
- merge across POS;
- merge prohibited material-label partitions;
- decide whether a source sense disappears;
- construct final accepted topology.

The model MAY be asked bounded questions such as:

> Are these two source senses substantially the same learner meaning?

or, where justified:

> Which of these code-owned candidate senses belong to the same learner concept?

The resulting topology must be constructed by deterministic Python.

# 7. Terminology

Use these terms consistently.

## Source Sense

A fine-grained lexical meaning record from the canonical Wiktionary-derived evidence.

## Learner-Meaning Container

A code-owned grouping of one or more source senses that represent substantially the same higher-level learner concept.

Example:

Source senses:

- S001 — water moves continuously downhill
- S014 — tears move down the face
- S027 — paint moves downward while wet

may, if semantic evidence supports it, become:

- G004 — flow or move continuously like a liquid

The learner-meaning container must retain all constituent source-sense IDs.

## Core Meaning

A learner-meaning container promoted to the main learner view.

## Additional Meaning

A valid learner-meaning container not promoted to Core Meanings.

No source sense is discarded merely because its container is Additional.

# 14. Define “Same Learner Meaning”

The prompt/benchmark must define this carefully.

Two source senses may be considered the same learner meaning when:

- they express substantially the same underlying concept;
- their differences are primarily context/example/application rather than a genuinely different lexical meaning;
- presenting them as separate top-level learner meanings would be unnecessarily duplicative.

They should remain distinct when:

- one expresses a materially different concept;
- one would require a learner to understand a different use of the word;
- combining them would create an overbroad or misleading definition;
- register/domain/material-label boundaries require separation.

Examples of potentially consolidatable patterns:

- liquid flowing;
- tears flowing;
- paint flowing;

may represent one broader “flow” concept.

Examples that should normally remain distinct:

- run = move quickly on foot;
- run = operate/function;
- run = manage;
- run = flow;
- run = extend in a direction.

Do not encode these examples as universal hard-coded rules.

# 17. Pair-Generation Efficiency

# 19. Code-Owned Clustering

Use the model judgments as semantic evidence, but Python must construct the containers.

A simple graph/union-find structure is acceptable if it satisfies semantic safety requirements.

Example:

S001 same S004
S004 same S007

may suggest:

G001 = [S001, S004, S007]

However, do NOT blindly apply transitive closure if it creates a semantic contradiction.

The benchmark must detect situations such as:

S001 same S004
S004 same S007
S001 distinct S007

and classify that cluster as inconsistent/ambiguous rather than silently merging all three.

Implement deterministic conflict detection.

Possible safe behavior:

- create cluster only when the evidence is internally consistent;
- leave ambiguous senses separate;
- mark the case for human review.

Prefer false split over destructive false merge in this benchmark.

# 23. Consolidation Review Rubric

Use a simple anchored rubric.

## Coverage

- 2 = all material source senses represented;
- 1 = questionable handling;
- 0 = missing/lost meaning.

## Merge Precision

- 2 = no clearly incorrect merges;
- 1 = one questionable merge;
- 0 = materially over-merged.

## Consolidation Efficiency

- 2 = obvious duplicate/near-duplicate senses consolidated;
- 1 = some unnecessary splitting;
- 0 = substantially fragmented.

## Learner Coherence

- 2 = resulting containers correspond to understandable learner meanings;
- 1 = some awkward boundaries;
- 0 = containers are misleading or incoherent.

## Overall

- FAIL
