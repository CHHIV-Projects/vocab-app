# M001.000 — Vocab App Repo Control Onboarding Reconnaissance

## Objective

Perform a reconnaissance-only onboarding assessment of the existing Vocab App repository so that future development can be governed by the accepted Repo Control II process rather than by legacy project-specific workflow conventions.

This milestone must reconstruct the project's historical development arcs, identify the latest trustworthy implementation baseline and any unfinished/current work, classify the existing governing documentation, and define the smallest safe transition into Repo Control-managed development.

Do not implement product changes in this milestone.

## Governing principle

Repo Control defines the development process. Individual repositories do not redefine Repo Control workflow, lifecycle, numbering, Git authority, Coder behavior, or evidence/closeout conventions based on legacy practice.

Historical Vocab artifacts remain historical evidence. They are not to be renamed or rewritten merely to conform retroactively.

After onboarding, new Vocab App development must follow the accepted Repo Control process and canonical milestone conventions.

Process/system boundary:

```text
Repo Control owns:
- lifecycle and milestone-state rules
- new milestone numbering/schema
- Coder authority and Git boundaries
- workflow procedure
- shared Agent Skills
- question/bug/test/closeout event handling
- evidence and acceptance flow

Vocab App owns:
- product goals and product history
- vocabulary-learning domain context
- application architecture
- project-specific technical constraints
- product-specific backlog and parking-lot content
```

## Phase 2 — Reconstruct historical project arcs

Use repository evidence, not memory alone, to reconstruct the major historical Vocab App development arcs.

Inspect, as relevant:
- milestone prompt/closeout files;
- context/history/handoff documents;
- Git history and tags/branches;
- README/project notes;
- code structure and tests when needed to validate what was actually implemented;
- prior architecture/workflow documents;
- any legacy milestone numbering conventions.

Produce a concise historical arc map.

For each identifiable major arc, record:
- historical name or best evidence-based description;
- approximate milestone range / historical identifiers;
- principal objective;
- key implemented outcomes;
- status: COMPLETE / PARTIAL / ABANDONED / SUPERSEDED / UNCLEAR;
- strongest evidence supporting the status;
- whether any unfinished work appears to remain relevant.

Do not force every old milestone into a new Repo Control arc. Summarize at the level useful for resuming development.
