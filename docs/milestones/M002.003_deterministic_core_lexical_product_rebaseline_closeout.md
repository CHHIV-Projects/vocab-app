# Milestone M002.003 — Deterministic Core Lexical Product Rebaseline

## 1. Scope Completed

Rebased the active learner lookup on deterministic Wiktionary/Wiktextract evidence and removed generative AI from the learner production path. Preserved compatible practice, translation, audio, saved-version, flagging, and historical research behavior.

## 2. Resulting Behavior

- One canonical source sense remains one learner meaning; distinct senses are not semantically merged.
- Meanings are grouped by POS. Up to five are shown initially per word, including one from each represented POS where practical, then filled in source order. Remaining senses are behind **Expand all meanings**. Labels are display-only and do not imply popularity.
- Synonyms remain attached to their exact source sense. Etymology wording/templates are source-derived and keep entry/etymology boundaries. U.S.-tagged IPA is preferred, with user-requested gTTS playback retained.
- Saved entries continue to show their immutable accepted snapshot. A later-dated installed dataset can provide an explicit Refresh candidate; only Save creates a new immutable version. Dataset status reports the installed identity/date, and the status control does not download or activate data.
- Existing accepted AI-era snapshots remain historical content. New deterministic saves do not populate model or prompt identity metadata.

## 4. Architecture / Integration Notes

- Removed the Ollama provider URL, local-AI network membership, and runtime cache mount from Compose. The learner workflow no longer imports or calls synthesis/provider code. The production image no longer copies `vocab_synthesis.py`; historical synthesis and benchmark code remain in the repository outside the learner image.

- No database migration was added. The existing immutable JSON snapshot/version architecture remains in use. Legacy model/prompt identity columns remain compatible with historical versions.
- The Compose app remains LAN-bound to its existing address. No public publication, router changes, proxy, VPN, authentication, or production deployment action was performed.

## 7. Deviations from Prompt

- Dataset download/import orchestration was not added. The prompt permits a safe installed-dataset status boundary when a full updater is not product-ready; the app reports current status and supports explicit Refresh from an already-installed newer dataset.
- The initial desktop/mobile browser acceptance used an in-memory persistence adapter; the required persistence boundary was subsequently verified by all isolated PostgreSQL integration tests and a browser Save/load round trip against the disposable database.
- No external mobile access was configured or tested, as required by the deployment boundary.

## 8. Known Limitations

- Refresh date comparison expects dataset version names with a terminal `YYYYMMDD` date, matching the current dataset naming scheme.
- The dataset control reports the active local installation; it does not download, validate, or activate a replacement dataset.
- External gTTS playback and translation provider behavior were not exercised.
- Isolated PostgreSQL tests used synthetic legacy metadata fixtures, not existing production accepted-history records; production records remain uninspected and unchanged.
- The disposable PostgreSQL browser run verifies the reviewed source against the isolated test database, not the deployed production image or database.

## 9. Deferred / Follow-Up Work

- Do not enable external mobile access as part of this milestone. Before publication, define and review a bounded access architecture with authentication, TLS, proxy/VPN boundaries, and an explicit deployment identity check.
- Dataset download, validation, and activation remain controlled operational steps outside the learner app.
- Any future migration or runtime verification must use an explicitly isolated test database and safe disposable data.

## 10. Recommended Next Milestone

Plan a bounded secure external-access milestone: threat model and select an authenticated access path (such as a managed VPN or authenticated reverse proxy), then validate it without opening direct public app/database ports. Keep this separate from lexical product behavior.
