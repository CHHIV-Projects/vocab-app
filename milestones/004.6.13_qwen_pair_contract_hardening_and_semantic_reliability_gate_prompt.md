# 1. Objective

M004.6.11 established the real bounded Qwen pair-judgment provider.

M004.6.12 proved complete word-level consolidation, durable reuse, resume behavior, and cached replay.

Those milestones also exposed one recurring semantic-provider failure pattern against real lexical evidence:

`decision = "merge"`
`reason = "specialized_subsense"`

This combination is invalid under the accepted M004.6.9 decision/reason contract.

Because:

- Qwen runs deterministically;
- retries preserve the same prompt/model/options/seed;
- the same invalid combination can repeat identically;
- retry exhaustion converts otherwise healthy lexical work into a terminally blocked partition;

this issue should be resolved before learner wording and Core/Additional ranking consume the consolidation layer.

M004.6.13 must harden the existing pair-judgment contract so ordinary valid lexical pairs are not unnecessarily blocked by deterministic decision/reason inconsistency.

This milestone does NOT change the fundamental semantic task.

The model still decides whether a pair should:

- merge;
- remain separate;
- remain uncertain.

The application still validates the answer.

# 2. Central Question

M004.6.13 must answer:

> Can the existing Qwen pair-judgment prompt/schema be constrained or clarified so that valid lexical evidence produces contract-consistent decision/reason pairs reliably, without weakening deterministic validation, changing the underlying consolidation policy, or increasing unsafe merges?

The goal is NOT:

"make Qwen always return something acceptable."

The goal is:

"make the requested semantic contract clearer and structurally harder to violate while preserving the conservative merge policy."

# 3. Why This Precedes Learner Wording

Do not begin learner wording or Core/Additional integration yet.

M004.6.12 demonstrated that the underlying workflow is healthy, but real words such as the tested `gecko` and `heron` partitions can become blocked solely because Qwen emits a semantically understandable but contract-invalid combination.

We should correct that boundary now rather than allow downstream learner-generation work to depend on avoidable terminal failures.

If M004.6.13 passes, the next milestone should resume the roadmap with learner wording and ranking integration.

# 12. Preferred Design Direction

Prefer structural prevention over retrying deterministic invalid output.

Investigate whether the structured-output schema can represent only valid combinations.

For example, conceptually:

- if decision=`merge`, reason must come from merge-compatible reasons;
- if decision=`keep_separate`, reason must come from separation-compatible reasons;
- if decision=`uncertain`, reason must be `insufficient_evidence`.

A JSON Schema using `oneOf`, discriminated branches, or another Ollama-supported equivalent may be appropriate.

However:

Do NOT assume Ollama/Qwen structured decoding supports the needed schema correctly.

Prove it in controlled tests.
