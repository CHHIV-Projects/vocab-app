## 4. Architecture / Integration Notes

### Phase A finding and exact mapping contract

Required provenance already existed; no new semantic mapping or schema was needed.
`grouped_content` resolves model aliases into canonical `source_sense_ids` before
building the candidate envelope. `validate_content` enforces known IDs, POS and
complete/nonduplicated coverage. Meaning groups have no separately persisted stable
group ID; this UI does not invent one.

For each meaning, the display projection:

1. takes unique canonical IDs from that meaning's recorded references, in order;
2. resolves each to exactly one sense in **that candidate's evidence_snapshot**;
3. requires the reference's POS to match the displayed section;
4. counts resolved senses, not gloss strings, prose similarity or the word's total
   source inventory;
5. surfaces unresolved/duplicate-snapshot/cross-POS references as errors rather than
   borrowing unrelated evidence; absent mapping is visibly not recorded.

Snapshots retain glosses, tags, examples, source sense/entry identities and locators,
source record hash, dataset/importer identity, evidence schema/hash and model/
prompt/policy/schema/packer/validator identities. Optional model digest can be
unrecorded. Examples and relations remain in existing Source Details/projections;
large raw records are not duplicated per meaning.

Saved provenance uses immutable accepted candidate/evidence snapshots. Retry uses
the exact accepted evidence; Refresh uses its own changed candidate evidence, not
the prior base's snapshot. Search uses its synthesis snapshot. Projections do not
query current lexical data or mutate candidates. Advanced candidate identity is
computed using the existing persistence hash convention, not copied from the
accepted base when a pending candidate is displayed.

The M002.000 resolver, accepted-versus-pending guards, actions and transactions are
unchanged. Accepted origin was already stored; loading the column is sufficient.
No new persistence fields or diagnostic retention were added.
