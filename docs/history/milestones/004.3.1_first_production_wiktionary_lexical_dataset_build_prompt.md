# Vocab App M004.3.1 — First Production Wiktionary Lexical Dataset Build

Prompt file:

`milestones/004.3.1_first_production_wiktionary_lexical_dataset_build_prompt.md`

Closeout file:

`milestones/004.3.1_first_production_wiktionary_lexical_dataset_build_closeout.md`

## 1. Purpose

Perform the first production-scale build of the deterministic lexical-data architecture accepted in M004.2 and implemented/tested with real-source fixtures in M004.3.

This milestone is the explicit Product Owner authorization to cross the production-scale Wiktionary import gate established in M004.3, subject to the safety/preflight conditions below.

Target pipeline:

Monthly English Wiktionary dump
    ->
Pinned Wiktextract extraction
    ->
English-focused structured evidence
    ->
M004.3 deterministic normalization
    ->
versioned evidence.jsonl
    ->
SQLite/FTS5 lexical.sqlite
    ->
validation
    ->
atomic active-version selection

WordNet remains a separate supplemental semantic source.

Do not implement GPT-OSS synthesis.

Do not integrate the new lexical dataset into the normal learner-facing Dictionary UI yet.

Translation remains a separate path.

## 2. Controlling prior architecture

Treat M004.2 and M004.3 as controlling.

The production architecture remains:

Wiktionary / Wiktextract
    = primary rich lexical evidence

WordNet
    = parallel supplemental semantic evidence

JSONL
    = canonical recoverable normalized evidence artifact

SQLite / FTS5
    = replaceable runtime lookup/index projection

gTTS
    = spoken pronunciation

PostgreSQL
    = user/application state and future accepted-entry provenance

GPT-OSS
    = future bounded derived synthesis only

Do not silently redesign these boundaries.

## 9. Extraction scope

The initial production lexical scope remains English-focused.

Capture:

- English lexical entries;
- relevant Translingual (`mul`) evidence where required by the established architecture;
- source-language / borrowing metadata attached to English entries.

Do NOT intentionally build a multilingual dictionary.

Do not retain unrelated language sections merely because they exist in the English Wiktionary dump.

Document the exact Wiktextract configuration used to implement this scope.

## 10. Conservative extraction resources

The first production extraction should favor system stability over fastest possible completion.

Do not automatically use every CPU core or maximize Wiktextract concurrency.

Use a conservative initial worker configuration appropriate to the 64 GB server, preferably no more than approximately four extraction workers unless direct Wiktextract requirements/evidence show a different bounded value is safer.

Maintain meaningful RAM headroom for Ubuntu and existing server services.

Record:

- worker count;
- peak or approximate RSS where measurable;
- CPU utilization observations;
- start/end time;
- extraction duration.

If extraction begins causing:

- severe memory pressure;
- swapping that materially threatens system stability;
- thermal instability;
- storage exhaustion;
- unrelated service failure;

stop the new build without disturbing existing application state and report.

Do not tune unrelated server hardware/software during this milestone.
